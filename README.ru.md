# Claude Context Meter

Маленький виджет поверх окон для Windows: показывает, насколько заполнен контекст у каждого
запущенного чата Claude — Claude Code и Cowork рядом — и сколько токенов уже потрачено
в окнах лимита.

![Виджет](docs/widget.png)

PowerShell и встроенный WPF. Без дополнительных зависимостей; данные чатов читаются локально.

## Вкладки Claude и Codex

Сверху можно переключаться между **Claude** (Claude Code и Cowork) и **Codex**.
Обновляется только выбранный агент: другая вкладка не сканирует папки, не читает логи
и не проверяет процессы. Её кэш остаётся в памяти; при возвращении чтение продолжается
с сохранённого места. Выбор вкладки сохраняется между запусками. Это управляет работой
виджета, а не запускает и не приостанавливает самих агентов.

Codex показывает до шести чатов с активностью за последние три часа, включая CLI и
desktop. Это недавние чаты, а не достоверный список открытых окон. Названия берутся из
`%USERPROFILE%\.codex\session_index.jsonl`, расход и размер контекста — из
`%USERPROFILE%\.codex\sessions\**\*.jsonl`. Если задан `CODEX_HOME`, используется он.
Кэшированные входные токены уже входят в `input_tokens` и второй раз не добавляются.
Процент обновляется после записи расхода в лог; при неизвестном размере окна показывается
`…`. Щелчок выводит окно приложения Codex вперёд.

Подвал Codex показывает записанные проценты лимитов за 5 часов и 7 дней. Если данных нет,
они старше двух часов, окно лимита имеет другую длительность или уже прошло время сброса,
показывается `—`. Субагенты не выводятся отдельными строками.

## Что написано в строке

```
CC  Handover 2026-08-13    ███████░░░   63%   1M
```

| Часть | Что означает |
|---|---|
| `CC` / `CW` | откуда чат — Claude Code или Cowork |
| название | настоящее имя чата, как его показывает приложение |
| полоска | заполнение контекста: зелёная, после 60 % жёлтая, после 80 % красная |
| `63 %` | последний запрос по отношению к окну |
| `1M` | размер самого окна |

Последняя колонка важнее, чем кажется: 80 % от 200k и 80 % от миллиона — очень разные
положения, а один только процент не даёт понять, в каком вы находитесь.

Строка тускнеет после 30 минут молчания. Под курсором показываются путь проекта, точное
число токенов, модель и когда чат был активен в последний раз. Щелчок по строке выводит
окно Claude вперёд, не трогая его размер: развёрнутое остаётся развёрнутым.

Подвал складывает все сессии, включая субагентов, по двум окнам лимита. Недельное окно
считается от недельного сброса аккаунта, а не за последние семь дней: токены до сброса уже
ни на что не влияют. Момент сброса виджет узнаёт сам — Claude Code записывает точное время
сброса в журнал каждый раз, когда сообщает о недельном лимите. Пока такой записи не было,
окно скользит по последним семи дням. Строкой ниже — когда следующий сброс.

Если приложение записало расход по плану, его процент стоит рядом с суммой, пока окно не
сменилось: пять часов для короткого, до следующего сброса для недельного. Приложение пишет
его лишь несколько раз в сутки, поэтому у числа старше четверти часа указано время.

## Запуск

Установленный виджет запускается как **`ClaudeContextMeter.exe`**. У этого файла есть имя,
издатель и иконка, а скрипт он выполняет внутри своего процесса, поэтому в диспетчере
задач виден один процесс *Claude Context Meter*, а не безымянный *Windows PowerShell*.
Консоль он не открывает: это оконная программа. Собирает его `build.ps1` из `launcher\`.

Из простой копии файлов — двойной щелчок по **`Start-ContextMeter.vbs`** или

```bash
powershell -STA -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File ClaudeContextMeter.ps1
```

`.vbs` нужен потому, что `powershell.exe` — консольное приложение: Windows выдаёт ему
консоль, а `-WindowStyle Hidden` прячет её уже после создания — отсюда чёрное окно при
каждом запуске. `.vbs` создаёт её скрытой сразу.

Виджет перетаскивается мышью и запоминает, куда его поставили. Крестик его **прячет** —
виджет продолжает работать и возвращается из значка в трее. По-настоящему завершает работу
только пункт **«Выйти»** в меню значка. Если запустить его ещё раз, пока он скрыт, окно
просто вернётся — второй копии не появится.

## Настройки

![Меню](docs/menu.png)

Щелчок по шестерёнке, правый щелчок по виджету или правый щелчок по значку в трее — везде
одно и то же. Двойной щелчок по значку показывает или прячет окно.

- **Запускать при входе в систему** — запись в обычной автозагрузке Windows (ключ `Run`
  вашей учётной записи), поэтому виджет виден во вкладке **«Автозагрузка»** диспетчера задач
  со своей иконкой, и выключить его можно и там. Галочка читается заново при каждом
  открытии меню и учитывает этот выключатель, так что вкладка и меню всегда согласны.
- **Язык** — английский, немецкий или русский, применяется сразу.
- **Частота обновления** — обычная (3 с), экономная (10 с) или минимальная (30 с). Такт и
  полное пересканирование папок растягиваются вместе: дорогая половина — именно
  пересканирование, и замедлить один такт значило бы сохранить расход и потерять свежесть.
- **Проверять обновления** — включено по умолчанию. Один раз при запуске спрашивает у
  GitHub, не вышла ли версия новее; если вышла, в обоих меню появляется строка
  **«Обновить до x.y.z»**, которая скачивает установщик. Любая неудача — нет сети, лимит
  запросов, нет релиза, к релизу не приложен установщик — означает просто «обновления нет»:
  проверка версии не имеет права сломать запуск.
- **Запоминать положение** — включено по умолчанию. Положение записывается в тот момент,
  когда вы отпустили окно, а не при выходе: иначе виджет, который убили, а не закрыли,
  терял бы место каждый раз. Проверяется оно по всему рабочему столу, поэтому место на
  втором мониторе — в том числе слева от главного, где координаты отрицательные —
  переживает перезапуск.

Виджет работает с приоритетом `BelowNormal` — процессор достаётся ему только тогда, когда
он никому не нужен. Вместе с настройкой частоты это честная замена «убрать его на
свободное ядро»: привязка к ядру не уменьшила бы работу, а только заперла бы её.

Команда записи строится из фактического расположения программы, а устаревший путь чинится
при следующем старте, так что переезд папки автозапуск не ломает.

До 1.3.1 автозапуск был задачей планировщика — поначалу затем, чтобы она ещё и
перезапускала виджет каждые 15 минут. От повтора отказались: перезапуск по таймеру прячет
то, что виджет убило. С тех пор задача делала ровно то же, что запись `Run`, только во
вкладке «Автозагрузка» её не было видно. В 1.3.2 задача при первом запуске заменяется
записью `Run`: сначала пишется запись, и только когда это удалось, задача удаляется. Так же
перенимается ярлык в папке автозагрузки от совсем старых версий.

## Значок в области уведомлений

Значок в трее отвечает на вопрос «работает ли он и куда делся». В его меню те же настройки
плюс **«Показать / Скрыть»** и **«Выйти»**, а при выходе значок явно удаляется, а не
остаётся призраком, который исчезает, только если провести по нему мышью.

Windows 11 складывает новые значки под стрелку `^`. Чтобы значок был на виду, перетащите
его оттуда на панель задач — это выбор пользователя, а не то, что программа должна решать
за него.

## Откуда берутся цифры

Всё читается из файлов, которые Claude и так пишет локально:

| Источник | Для чего |
|---|---|
| `%USERPROFILE%\.claude\projects\**\*.jsonl` | транскрипты Claude Code — расход токенов |
| `%APPDATA%\Claude\local-agent-mode-sessions` | транскрипты и записи чатов Cowork |
| `%APPDATA%\Claude\claude-code-sessions` | названия чатов Claude Code |
| `%USERPROFILE%\.claude\sessions` | какие сессии действительно запущены |
| `%APPDATA%\Claude\plan-usage-history.json` | проценты расхода по плану |

Ничего из ваших чатов наружу не уходит. Виджет обращается ровно к одному узлу, и только
если включена настройка **«Проверять обновления»**: к `api.github.com`, чтобы спросить у
этого репозитория, не вышла ли версия новее. В запросе не передаётся ничего, кроме самого
запроса. Выключите настройку — и виджет не делает ни одного сетевого соединения.

Единственный вызов Windows API поднимает окно Claude, когда вы щёлкаете по строке.

Своё состояние виджет держит в `%LOCALAPPDATA%`: положение окна, выученные размеры окна
контекста по моделям, язык и отладочный лог.

### Как определяется размер контекста

Нигде на диске не записано, на каком окне работает чат, поэтому виджет выясняет это сам.
Запрос больше 200k может существовать только на большом окне — это считается
доказательством. Если его нет, смотрится метка `[1m]` в имени модели, затем то, что за этой
моделью замечали раньше, — и это помнится между перезапусками. И только когда свидетельств
нет никаких, берётся предположение.

## Требования

Windows с Windows PowerShell 5.1 — он есть в Windows 10 и 11. Больше ничего.
